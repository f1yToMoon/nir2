## Контекст

ТЗ зафиксировало `SEAWEEDFS_VERSION=3.97` (тег на Docker Hub, создан 2025-09-01).
При тестировании стенда обнаружено: SeaweedFS 3.97 принимает PutObject-запросы
с `Content-Encoding: aws-chunked` (`x-amz-content-sha256: STREAMING-AWS4-HMAC-SHA256-PAYLOAD`)
и сохраняет тело запроса в сыром виде — с заголовками chunk-размера и chunk-подписью:

```
29d;chunk-signature=bb5d4463...{"format-version":2,...}0;chunk-signature=...
```

Это поведение противоречит RFC 7230 §4.1: сервер обязан декодировать
chunked transfer encoding перед сохранением данных.

При последующем чтении метаданных Iceberg Jackson выбрасывал:
```
JsonParseException: Unexpected character ('d' (code 100))
```
потому что вместо JSON получал заголовок чанка `29d;...`.

Аналогичная ошибка была воспроизводима в обоих провалившихся тестах smoke:
`slot_header_X-CAPL-Slot` и `flink_streaming_commit`.

## Причина выбора aws-chunked AWS SDK

Iceberg 1.12 использует AWS SDK v2 для S3FileIO. SDK v2 применяет
`STREAMING-AWS4-HMAC-SHA256-PAYLOAD` по умолчанию при подписанных PUT-запросах
(`S3Configuration.chunkedEncodingEnabled=true` — default). Отключение
недоступно через конфигурационные свойства Iceberg без модификации исходного кода.

## Решение

Обновить SeaweedFS до `4.48` (`chrislusf/seaweedfs:4.48`, создан 2026-09-28).
В версии 4.48 chunked-тела декодируются корректно до сохранения.

Проверка совместимости:
- Команда запуска SeaweedFS не изменилась между 3.97 и 4.48.
- После обновления все 8 smoke-тестов прошли успешно.

Изменения:
- `infra/.env`: `SEAWEEDFS_VERSION=4.48`
- `infra/.env.example`: `SEAWEEDFS_VERSION=4.48` с комментарием причины.

## Последствия

**Положительные:**
- Iceberg metadata-файлы записываются и читаются корректно.
- Все smoke-тесты проходят (8/8).

**Отрицательные / риски:**
- SeaweedFS 4.x — мажорная версия; потенциально меняет внутренний формат данных.
  Для этапа 0 данные предыдущих прогонов не нужны, том `s3-data` был очищен.
- Минорные изменения S3 API между 3.97 и 4.48 не выявлены при тестировании,
  но специального аудита не проводилось.

**Действие:** Если при будущих прогонах обнаружатся S3-несовместимости,
рассмотреть миграцию на MinIO Garage или изоляцию через `CATALOG_S3_*`-настройки.
