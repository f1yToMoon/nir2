# ADR-007: Прозрачность прокси — уровень HTTP-сообщения, коды 2xx коммита, классификация по телу

**Статус:** Предложено (этап 2)
**Дата:** 2026-10-31
**Связано с:** FR-PROXY-1, FR-PROXY-7, `tz/04_interfaces.md` §1.1–1.2, `AGENTS.md` (ограничение 1)

## Контекст

ТЗ требует, чтобы прокси передавал запросы и ответы «без изменений, кроме hop-by-hop заголовков». На этапе 2 проверки на моке каталога (`tests/unit/test_proxy_transparency.py`) и на стенде (`tests/integration/test_proxy_stage2.py::test_responses_identical_to_catalog`) выявили, что понимать «без изменений» нужно на уровне HTTP-сообщения (метод, цель запроса, поля заголовков, содержимое), а не байтов соединения, и нашли три расхождения реализации прототипа этапов 0–1 с этим требованием.

## Решение

1. **Что сохраняется побайтно:** тело запроса и тело ответа (ответ — сырые байты, без декодирования `Content-Encoding`), путь и query в исходной кодировке (`%1F`, `%2F`, отсутствие `?` при пустом query), список полей заголовков с повторами и значениями (кроме hop-by-hop: `Connection` и перечисленные в нём, `Keep-Alive`, `Proxy-*`, `TE`, `Trailer(s)`, `Transfer-Encoding`, `Upgrade`), включая `Host` (пересылается как получен). Прокси не добавляет заголовков: у `httpx` убраны заголовки по умолчанию (`User-Agent`, `Accept-Encoding` и др.), у `uvicorn` — `server` и `date`.
2. **Что не сохраняется (ограничение ASGI/h11, не влияет на семантику):** reason-phrase строки статуса (каталог Jetty: `500 Server Error`, прокси: `500 Internal Server Error`) и регистр имён заголовков. Reason-phrase клиенты обязаны игнорировать (RFC 9112 §4), имена полей нечувствительны к регистру (RFC 9110 §5.1). Клиенты Iceberg (Java `HTTPClient`, PyIceberg) используют только код статуса и тело.
3. **Исправления прототипа этапов 0–1:** (а) ответ передавался декодированным (`httpx.Response.content`) с удалённым `Content-Encoding` — теперь сырые байты и исходный заголовок; (б) `httpx` добавлял к запросу каталога свои заголовки по умолчанию — убраны; (в) при пустом query к пути добавлялся `?`, а `%1F` в пути вызывал ошибку — цель запроса берётся из `raw_path`/`query_string`.
4. **Успех коммита — любой 2xx.** Каталог отвечает на `POST /v1/transactions/commit` кодом 204 (обнаружено при снятии фикстуры), на коммит таблицы — 200. Постановка в очередь обогащения и освобождение удержания по коммиту конкурента выполняются при 2xx.
5. **Классификация `op_class` по телу ограничена классом коммита Iceberg.** Статический `INSERT OVERWRITE … PARTITION (…)` коммитится тем же `OverwriteFiles` (`SparkWrite.java:374-404`), что и CoW DML, и summary у них одинаковы по ключам → по телу классифицируется как `cow_dml`. Истинный тип даёт привязка слот → `op_id` (FR-PROXY-4); в сценариях S0–S6 статический overwrite не используется (S4 — dynamic, `replace-partitions=true` → `overwrite`).
6. **Режимы:** `proxy.mode = full | passthrough` (`passthrough` — только пересылка, без разбора, журнала и удержаний; переключается `PUT /v1/debug/mode`); контрольные прогоны `bypass` по-прежнему задаются маршрутизацией клиентов (`CATALOG_ROUTING=bypass`, клиенты → каталог напрямую), прокси в них не участвует.

## Последствия

- Проверка «тело и заголовки не изменены» выполняется сравнением SHA-256 тела и мультимножества заголовков на входе прокси и на входе транспорта `httpx` (`IntegrityTransport`, доля выборки `proxy.integrity_sample_rate`, по умолчанию 1 %), результат — метрика `capl_body_integrity_total{result}`.
- Сравнение ответов прокси и каталога в тестах ведётся при одинаковом `Host`: каталог вписывает полученный `Host` в HTML-страницы ошибок.
