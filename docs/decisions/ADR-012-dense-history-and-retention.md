# ADR-012: Пики истории между выборками и пересчёт предварительного R

**Статус:** исправление реализации проверок и применение принятого правила ADR-008.
**Дата:** 08.11.2026. Научные пороги и политика P0 не меняются.

## Отказ прежней квалификации

Семь полных прогонов `-adr011-20261108` выполнены при R=600 с. Все проверки данных,
стоимости, свежести и пяти инвариантов прошли. Однако прежний `stage3_checks.py`
ошибочно принимал эту серию: максимумы `table_meta` измеряются раз в 30 с, а верхняя
граница R вычислялась без обязательного сравнения с настроенным значением.

В S1 максимум выборок — 1405 снимков / 1393275 Б. По журналу успешных запросов
нижняя и верхняя границы максимума совпали: **1459 снимков**, выше предела 1452.
Пик подтверждён в 13:35:54 UTC. Интервалы запросов и ID —
`results/stage-3/series-adr011-20261108/history-bounds-stage3-S1-P0-mid-s11-adr011-20261108.json.gz`.
Старый полный проверяющий скрипт дал 0 отказов; исправленный — ровно два:
пик S1 и R=600 с > верхней границы 597,4 с (`checks-{sampled-before,dense}.json`).
Прежняя серия сохраняется полностью и не выдаётся за принятую квалификацию.

## Исправленная проверка

Изменение метаданных происходит между `forwarded_at` и `responded_at` успешного
запроса. Для верхней границы добавления учитываются с начала интервала, удаления —
с конца; для нижней — наоборот. При совпадении границ используется консервативный
порядок. ID дедуплицируются; удалённый ID не появляется снова при неопределённом
порядке ответов. Начальное состояние — один снимок `golden`, измеренный до писателей.
Отсутствующий интервал, неизвестный удалённый ID или удаление `golden` дают отказ.

Это границы числа снимков при полноте журнала, а не оценка по средней интенсивности.
Полнота линии дополнительно проверяется инвариантами. Регрессия создаёт 1453 снимка
и удаляет их до следующей выборки: проверка видит превышение, хотя последнее
наблюдение содержит два снимка. Максимум байтов метаданных явно называется
наблюдённым; период выборки — 30 с.

## Пересчёт R по принятому правилу

ADR-008 предписывает пересчитать предварительный R по измерениям; решение автора
требуется при отсутствии общего интервала. По всей серии D_hist,max=37,373262 с,
R_low=2·D_hist,max+5·60=374,746524 с. Интенсивность S1, включая управляемые фиксации,
равна 2,2087633704/с; R_high=1452/rate−60≈597,4 с.

Для новой квалификации выбирается кратное существующему I=60 с значение с
округлением верхней границы вниз: floor(R_high/I)·I=**540 с**. Оно выше R_low.
Расчёт не заменяет повторной проверки плотной границы: всплески и задержки expire
проверяются новой серией.

Меняется только предварительный срок фонового хранения S0–S5; интенсивности,
операции, зерна, размеры данных, длительности и пороги сохраняются. S6 с отдельным
управляемым expire не меняется. Полностью повторяются S4/S5, затем S0×2/S1–S3 с
новыми run_id. Срок выбран до новой серии, без P5/P6 и до E3; неудачная серия R=600
не исключается из истории проверки инструмента.
