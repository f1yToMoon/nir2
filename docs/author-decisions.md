   # Решения автора

   ## 2026-11-01. NFR-1 (этап 2)
   Решение: (б) + (а). Порог NFR-1 (медиана ≤ 5 мс) не меняется.
   (б) В сценарии добавляется периодический expire_snapshots, чтобы ограничить историю таблицы (модельное допущение, не практика эксплуатации).
   (а) Область применимости NFR-1 фиксируется в отчёте и ADR-008.
   Срок хранения снапшотов выбирается с учётом длительности операций: операции не должны терять базовый снапшот во время работы.


   ## 2026-11-04. Ограничение 6 в AGENTS.md (метка base_expired)
   Подтверждаю изменение из коммита 65c4fbe: ValidationException «Cannot determine history …» размечается как base_expired, а не data_conflict.
   Условие: на этапе 3 метка base_expired ставится только при подтверждении данными (базовый снапшот или следующий за ним отсутствует в метаданных, а в журнале компоненты фиксации есть expire между стартом операции и отказом). Без подтверждения — отдельная метка ошибки runner, которая не исключается из анализа.
   base_expired учитывается в потерянных вычислениях отдельной строкой.
