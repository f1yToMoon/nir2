## Формат и границы Codex

Официальные источники, открытые при подготовке: [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Skills](https://learn.chatgpt.com/codex/build-skills), [Hooks](https://learn.chatgpt.com/docs/hooks).

Нативная роль задаётся отдельным TOML в `.codex/agents/` с `name`, `description`, `developer_instructions`. Проектные навыки обнаруживаются в `.agents/skills/<name>/SKILL.md`. Роль наследует доступные разрешения, провайдера и MCP родителя: список инструментов Claude и модель Opus не переносятся буквально. Запрет ревьюеру менять реализацию сохранён в инструкции роли; это правило рабочего процесса, а не отдельная изоляция файловой системы. Общие хуки по-прежнему защищают существующие ревью и решения автора. Нельзя утверждать, что нативная роль физически имеет запись только в один новый файл, если это не ограничено внешним sandbox.

Независимость приёмки требует нового контекста без истории реализации, зафиксированного коммита и запрета исполнителю менять артефакты во время ревью. При ограничениях API текущей сессии используется новый CLI/app-server с доступом к установленной роли. Самопроверка и smoke роли не заменяют ревью этапа. Предел — 3 раунда за один запуск stage; переназначение роли его не сбрасывает.
