## Подключение

Codex поддерживает проектный `.codex/hooks.json`. В установленной версии `codex features list` показывает `hooks stable true`; дополнительный `.codex/config.toml` не нужен. Существующая глобальная конфигурация и сторонние пользовательские хуки не изменяются. Источники: [официальная документация Hooks](https://learn.chatgpt.com/docs/hooks), [Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced).

В конфигурации два события:

| Событие | Адаптер | Действие |
| --- | --- | --- |
| SessionStart | `scripts/hooks/codex_session_start.py` | Состояние этапов, последнее ревью, ID открытых замечаний, решения G1/G2, предел трёх раундов, обязательная остановка после этапа |
| PreToolUse | `scripts/hooks/codex_pretool.py` | Защита терминальных команд и файловых правок; вызов общих проверок Claude |

В проектной конфигурации `Stop` отсутствует. После приёмки этапа агент делает отчёт, коммит, push и останавливается; последующая проверка — пользователем в ChatGPT Web. Принятие этапа требует отдельного независимого ревью по зафиксированному коммиту.

Codex передаёт JSON на stdin: `cwd`, `hook_event_name`, `tool_name`, `tool_input`. Для `Bash` и `apply_patch` содержимое находится в `tool_input.command`. Терминальный `exec_command` соответствует имени `Bash`; редактирование — `apply_patch` с алиасами Edit/Write. Запрет возвращается кодом 2 и причиной в stderr, что поддерживается данной версией CLI.

Корень вычисляется через `git -C <cwd> rev-parse --show-toplevel`; команды конфигурации также находят адаптер от корня Git. Запуск из подкаталога не меняет область защиты. В патчах проверяются **все** Add/Update/Delete/Move пути, включая источник и назначение перемещения, абсолютные пути, `..` и символьные ссылки. Неизвестный формат отклоняется. Существующие ревью неизменяемы; новый файл следующего раунда разрешён. Новые `.codex/` и адаптеры входят в защищённую область, в том числе при коммите через старый Claude-хук.

## Необходимое действие пользователя

Официальный механизм требует доверия точному определению каждого нового хука. Агент не редактирует хранилище доверия и не использует `--dangerously-bypass-hook-trust`.

1. Запустить `codex --enable hooks -C /home/an/nir`. Если Codex запросит доверие проекту, проверить путь `/home/an/nir` и подтвердить его самостоятельно.
2. Открыть `/hooks`, проверить источник `/home/an/nir/.codex/hooks.json` и доверить только два подготовленных хука CAPL: SessionStart и PreToolUse. Не требуется доверять сторонним глобальным хукам.
3. Перезапустить или возобновить рабочую сессию после доверия, чтобы SessionStart выполнился при новом старте/возобновлении. Эта сессия началась до добавления конфигурации, поэтому её ранний SessionStart нельзя считать проверкой новых хуков.

Для фактической проверки перехвата подготовлен отдельный временный репозиторий:

```bash
codex --enable hooks -C /tmp/capl-codex-hooks-sz5alpxk
# Проверить доверие именно этому временному проекту; затем /hooks
# Доверить только два project hook из его .codex/hooks.json и выйти из сессии.
python3 /home/an/nir/scripts/hooks/verify_codex_runtime.py --run /tmp/capl-codex-hooks-sz5alpxk
```

Временные хуки используют копии тех же адаптеров и прозрачную оболочку, которая записывает факт вызова и exit code, не меняя решение. Проверка запускает настоящий `codex exec` и требует событий SessionStart/PreToolUse для шести случаев: разрешённый Bash, разрешённый apply_patch, запрещённый stage-тег, патч нескольких файлов с защищённым удалением, удаление существующего ревью, заполнение решения автора. Дополнительно сверяются наличие разрешённых файлов, отсутствие stage-3 и сохранность запрещённых к изменению фиктивных файлов. Транскрипты и `runtime-results.json` сохраняются во временном репозитории. Требуется штатная авторизация Codex; токены нигде не копируются.

Без доверия программа завершится кодом 3 **до запуска модельных тестов**. Это ожидаемая точка остановки, не PASS фактического перехвата. При удалении временного каталога его можно подготовить заново командой `python3 scripts/hooks/verify_codex_runtime.py --prepare`, затем доверить новый путь вручную.

## Ограничения

Это защита поддерживаемых вызовов инструментов, а не изоляция произвольного исполняемого кода. Официальная документация отдельно указывает, что `write_stdin` не запускает PreToolUse повторно, а некоторые специализированные инструменты обходят общий путь. Нельзя использовать интерактивный терминал, закодированные программы или иные каналы для обхода защиты. Терминальный анализ сохраняет исходные проверки Claude и добавляет нормализацию распространённых команд; он не является полным интерпретатором shell. Для механически обязательной защиты от любого процесса нужны внешние средства контроля доступа, что не входит в данный перенос.

Этап 3 остаётся в работе. После подключения и проверки хуков требуется вернуться к полным опытам с исправленным учётом (ADR-010), затем выполнить независимое ревью этапа; тега `stage-3` пока нет.
