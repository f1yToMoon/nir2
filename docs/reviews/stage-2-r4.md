Что опровергло бы гипотезу этапа и мог ли тест это получить:
- **NFR-1 в режиме ADR-008.** Опровержением была бы верхняя граница ДИ полосы > 5 мс или разность p95 > 15 мс при истории 1307–1452 снапшотов Spark-размера. Тест это получить может: на той же проверке упал `r8-boundary`. В `r9` этого не произошло.
- **Метки `base_expired`.** Опровержение — отказ с этим сообщением без удаления истории. Unit-тест этого обнаружить не может, нужна проверка по данным на этапе 3 (S2-R4-05).
- **Журнал, следы, прозрачность, fail-open** — без изменений с r3. Проверки ненулевые, с `assert`.

## Не удалось проверить

- Накладные расходы при параллельной нагрузке S1 (7 писателей, 2,2 коммита/с через прокси, обогащение на каждом коммите) и для клиента Spark (Java HTTP-клиент). Бенчмарк — последовательный клиент PyIceberg; перенос из r1–r3. Для проверки нужен замер bypass/proxy в прогоне сценария S1 (этап 3, ср. AC-5).
- Длительность и CPU задания `expire_snapshots` при ~1320 оставшихся снапшотах (S2-R4-03): Spark-задание на стенде не запускал.
- Свежий `make proxy-verify` (≈ 1,4 ч) не запускал. Стенд не менял, запросы к нему только на чтение (`docker exec … cat`).
