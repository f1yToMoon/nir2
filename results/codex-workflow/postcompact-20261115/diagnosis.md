# PostCompact: отдельная диагностика 15.11.2026

Пользователь сообщил об ошибке PostCompact после автоматического сжатия контекста.
Источник регистрации установлен: **пользовательский Caveman**,
`~/.codex/hooks.json:73`; проект CAPL не содержит PostCompact.
Обработчик — `caveman-proxy native-hook codex` с `native-hook-fast.js`.
В установленном адаптере `native-hook-fast.js:496–499` PostCompact, как SessionStart,
передаётся полному CLI; `:457–472` ограничивает дочерний вызов 3000 мс.
Это описание кода, а не доказательство тайм-аута в исходном событии.

`~/.caveman/runtime/native-events.jsonl` содержит PreCompact текущей сессии
в 11:51:29.426 UTC. Исходный stderr/код ошибки PostCompact в доступных
daemon.stderr.log, logs_2.sqlite и rollout не найден. Первичный просмотр журналов
не позволял выбрать между гипотезами тайм-аута, версии и формата. Дополнительная
проверка схем и парсера ниже установила конкретную несовместимость stdout.
Она не восстанавливает отсутствующий stderr исходного события.

Повтор непосредственно настроенного обработчика с диагностическим PostCompact
дал exit 0, stderr пустой, 0,118 с; JSON stdout содержит
`hookSpecificOutput.hookEventName=PostCompact` и additionalContext.
Результат с удалённой локальной подписью и SHA-256 оригинала:
`handler-probe.json`. Это самостоятельная проба обработчика,
не повтор compaction движком. CLI `codex --version`: 0.167.0; daemon в журнале
запрашивает модели с client_version=0.169.0. Разница версий сама по себе
не устанавливает причину ошибки.

Свежий `hooks/list` для `/home/an/nir`: ошибок и предупреждений 0;
оба проектных хука **enabled=true, trustStatus=trusted**. Их currentHash:

| Событие | SHA-256 |
| --- | --- |
| PreToolUse | 35175006e3d53a4eed05766692e53d254af74cee218712efe82c6d5e8075c46e |
| SessionStart | 9829a42c4758e6b1f2a4a3cea4db00255125fe4475283234b6b6dc0a4189a22e |

SessionStart CAPL присутствует в developer-контексте возобновлённой сессии.
После compaction PreToolUse реально отклонил команду в 11:55:05.419 UTC:
чтение защищённого пути, объединённое с перенаправлением `2>/dev/null`,
консервативно распознано как защищённая запись. Чтение отдельными командами
без перенаправления прошло. Это подтверждает активность защиты, но не является
новым полным прогоном шести runtime-кейсов; они сохранены отдельно за 08.11.

## Установленная несовместимость формата ответа

Дополнительная проверка официальных схем **обеих установленных версий** установила
конкретный дефект контракта. В stdout Caveman присутствует `hookSpecificOutput`
с `hookEventName=PostCompact`. Схемы `rust-v0.167.0` и `rust-v0.169.0` для
`post-compact.command.output` разрешают только `continue`, `stopReason`,
`systemMessage`, `suppressOutput`; `additionalProperties=false`.

Проверка сохранённой пробы отвергает ровно одно верхнеуровневое поле:
`hookSpecificOutput`. Результат, URL исходников и SHA-256 схем —
`wire-validation.json`; сами две схемы сохранены рядом. Для этого вывода
не нужен полный экспорт пользовательской конфигурации.

Код Codex `rust-v0.169.0`, пути от `codex-rs/hooks/src/`:

- `schema.rs:178–185`: `PostCompactCommandOutputWire` имеет
  `serde(deny_unknown_fields)` и только универсальные поля;
- `engine/output_parser.rs:250–257,345–357`: десериализует именно этот тип,
  возвращая None при несовместимости;
- `events/compact.rs:276–310`: даже при exit0 отклонённый JSON получает
  `HookRunStatus::Failed` и сообщение
  `hook returned invalid PostCompact hook JSON output`.

Таким образом, код0 процесса Caveman совместим с ошибкой на уровне Codex:
проверена несовместимость stdout, а не предполагаемый тайм-аут. Исходный stderr
того события по-прежнему не восстановлен; текст ошибки выше взят из кода
движка, а не выдан за найденную запись журнала. Исправление вывода требуется
в обработчике Caveman; проектные CAPL SessionStart/PreToolUse от него не зависят.

Настройки, доверие и механизм приёмки не менялись. Полная пользовательская
конфигурация и базы Codex не копируются в репозиторий. Защита действует;
этап 3 продолжается. Исправление провайдером формата PostCompact остаётся отдельным вопросом.
Официальное описание событий: https://developers.openai.com/codex/hooks/ .
