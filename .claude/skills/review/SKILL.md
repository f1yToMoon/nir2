---
name: review
description: Запустить независимое ревью этапа НИР субагентом stage-reviewer и получить вердикт. Использовать после каждой завершённой итерации этапа, перед тегом stage-N и перед контрольными точками.
argument-hint: "[номер этапа]"
---

Запусти субагента `stage-reviewer` для этапа $ARGUMENTS (если номер не указан — для текущего этапа: последний тег `stage-*` + 1).

Перед запуском:

1. Убедись, что все изменения закоммичены (`git status --porcelain` пуст). Если нет — сначала закоммить; ревью проводится по коммиту.
2. Определи номер раунда K: следующий после максимального в `docs/reviews/stage-<N>-r*.md`.

Передай субагенту задачу: «Проведи ревью этапа <N>, раунд <K>, по docs/REVIEWER.md. Запиши docs/reviews/stage-<N>-r<K>.md».

После ответа субагента:

1. Прочитай созданный файл ревью целиком.
2. Закоммить только его: `git add docs/reviews/stage-<N>-r<K>.md && git commit -m "review: stage-<N> r<K> <вердикт>"`.
3. Кратко сообщи вердикт и список BLOCKER/MAJOR.

Не оспаривай и не правь ревью. Если считаешь замечание ошибочным, это решается в следующей итерации: опровержение с доказательством (`файл:строка`, число) записывается в отчёт этапа, и следующий раунд ревью его проверит.
