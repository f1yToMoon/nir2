Номер N берётся из поручения; если не задан — последний stage-тег + 1. Это адаптация .claude/skills/review/SKILL.md для Codex.

Перед запуском:
1. Прочитай docs/REVIEWER.md целиком и AGENTS.md. Проверь чистое дерево git status --porcelain; сначала закоммить изменения. Зафиксируй полный git rev-parse HEAD. Определи K как следующий после максимального docs/reviews/stage-N-r*.md; не переиспользуй номер.
2. База — Reviewed-Commit предыдущего раунда этапа, иначе stage-(N-1). Передай N, K, полный SHA, базу, пути отчёта, ADR, исходных измерений и критерии docs/REVIEWER.md. Для переноса отдельно передай docs/codex-workflow.md и доказательства работы хуков/роли.
3. Запусти нативного stage-reviewer отдельным субагентом с новым контекстом без истории реализации (fork_context=false, fork_turns=none или эквивалент доступного API). При API, не умеющем выбирать установленную роль, используй новый Codex CLI/app-server, способный выбрать её; не подменяй проверку роли обычным агентом с похожим сообщением. Не передавай исполнителю роль собственного ревьюера.
4. Поручение: «Проведи ревью этапа N, раунд K, коммита SHA по docs/REVIEWER.md. База BASE. Проверь артефакты REPORT/RESULTS. Запиши только новый docs/reviews/stage-N-rK.md. Реализацию и существующие ревью не меняй, не коммить. Проверь HEAD перед началом и завершением».
5. Дождись результата; не меняй HEAD/артефакты во время ревью. Сохрани доказательство реального запуска, отдельного контекста и получения результата без токенов и посторонних настроек. Если запуск не выполнен — ревью не состоялось.

После ответа:
1. Прочитай новый файл целиком. Сверь Stage/Round/Reviewed-Commit/Base, обязательные разделы, включая состязательный проход. Если файл отсутствует или относится к другому SHA, приёмку не объявляй.
2. Закоммить только новый файл ревью: git add docs/reviews/stage-N-rK.md; git commit с сообщением review: stage-N rK VERDICT. Отчёт ревьюера не правь.
3. Сообщи вердикт и BLOCKER/MAJOR. При несогласии запиши опровержение с файл:строка и числом в «Ответы на ревью» отчёта этапа; следующий независимый раунд проверит его.
4. Управление исправлениями и предел трёх раундов за запуск — у stage; дополнительный review не обходит этот предел. Ревьюер не запускает долгие эксперименты и не исправляет реализацию.

Шаблон результата и критерии полностью определены docs/REVIEWER.md §5–6; роль — .codex/agents/stage-reviewer.toml. Доступ Read/Grep/Glob/Bash/Write Claude сопоставлен чтению/rg/терминалу/apply_patch Codex, но право записи ограничено новым файлом ревью инструкциями роли.
