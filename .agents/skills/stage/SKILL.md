Номер N берётся из поручения автора. Это адаптация .claude/skills/stage/SKILL.md для Codex; содержательные требования исходника сохранены.

1. Прочитай AGENTS.md, docs/REVIEWER.md целиком, раздел N в tz/06_implementation_plan.md, отчёт этапа и все docs/reviews/stage-N-r*.md. Последнее CHANGES_REQUESTED задаёт обязательные задачи по всем ID. Составь список задач по ID или плану этапа; вместо Claude TaskCreate используй доступный план и раздел отчёта.
2. Реализуй этап по плану и чек-листам docs/REVIEWER.md §3–4. Не ослабляй пороги, assert и ожидания ради PASS. При трудной проверке исправляй реализацию. Поведение Iceberg/Spark подтверждай кодом конкретной версии third_party/iceberg-src с файл:строка; при отсутствии используй scripts/fetch_iceberg_src.sh. Коммить по логическим шагам.
3. Выполни все обязательные проверки и самопроверку. Обнови docs/stage-N-report.md по шаблону: числа, единицы, команды, параметры, версии, SHA, пути исходных измерений; «Ответы на ревью» по каждому ID, с доказательством исправления или опровержения. Обнови docs/CHANGELOG.md. Закоммить, рабочее дерево должно быть чистым до независимого ревью.
4. Используй навык review (.agents/skills/review/SKILL.md). Ревью выполняет нативная роль stage-reviewer отдельным субагентом с новым контекстом без истории реализации. Передай только зафиксированный SHA, N/K, базу, инструкции, критерии и пути артефактов. Самопроверка не заменяет ревью.
5. При CHANGES_REQUESTED исправь все замечания и повтори проверки, отчёт, коммит, независимый раунд. За один запуск stage — не более трёх раундов. После третьего CHANGES_REQUESTED остановись и перечисли оставшиеся ID и причины; не обнуляй счётчик перезапуском роли.
6. При PASS/PASS_WITH_NOTES для этапов кроме 1 и 4 перенеси MINOR в задачи следующего этапа до финального проверяемого коммита; затем поставь stage-N на текущий покрытый ревью HEAD штатной командой git tag stage-N. Выполни git push и публикацию соответствующего тега без force; сравни локальный и удалённый SHA. После приёмки остановись перед следующим этапом. Изменение реализации/отчёта после ревью требует нового раунда, если review_covers_head его не покрывает.
7. На этапах 1 и 4 после PASS* заполни отчёт G1/G2 по шаблону с рекомендацией, оставь «Решение автора» пустым, закоммить и опубликуй; остановись для решения автора. Не ставь тег до решения и штатной проверки хука. Не записывай решение сам.
8. При любой предусмотренной остановке перечисли предложения ревьюера в REVIEWER.md из всех раундов; решение об их включении принимает автор. Передай этап, ветку, полный SHA, чистоту дерева, проверки, исходные измерения, вердикт и ограничения.

Полные журналы сохраняй в файлах. Если Caveman сократил обязательный документ или результат проверки, дочитай полный текст из файла/артефакта. Не выдавай сокращённый вывод или прошлый прогон за новые доказательства.
Существующие ревью и решения автора неизменяемы. Не обходи защиту или доверие хукам, не меняй механизм приёмки без отдельного поручения автора. Stop-хук для бесконечного продолжения запрещён.

Локальные защитные ограничения Claude сохраняются и для Codex: не выполняй sudo; rm -rf с целью от / или ~; git push --force или -f; git reset --hard; docker system prune; docker volume rm; docker compose down -v; make clean. Это ограничения проекта, а не разрешение копировать .claude/settings.local.json или глобальные настройки. Общий PreToolUse должен механически проверять эти классы команд, включая варианты глобальных Git-флагов; наличие текста навыка само по себе не доказывает блокировку.
